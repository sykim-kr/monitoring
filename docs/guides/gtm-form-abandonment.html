데모 신청 폼 이탈(Form Abandonment) 추적
— Google Tag Manager 설정 가이드

대상: 내부 태깅 담당자 · 작성: OCEO 팀(크롱) · 2026-05-25 · 대상 페이지: /solutions/demo-request

이 문서는 데모 신청 폼의 "어디서 이탈하는지"를 측정하기 위해 GTM에 추가해야 할 이벤트·트리거·태그를 단계별로 정리한 실무 가이드입니다. 코드 배포 없이 GTM 컨테이너 작업만으로 구현 가능합니다.

왜 지금 필요한가
지난주(5/18~5/24) 데모 CTA 클릭은 12건 발생했으나 폼 제출 완료(submit_demo_request)는 0건. 추적 자체는 정상 작동(테스트로 검증 완료)이며, 실제로 제출까지 이어진 사용자가 0명이었습니다. 즉 "클릭 → 폼 작성 → 제출" 구간에서 100% 이탈. 어느 지점에서 이탈하는지를 보려면 "시작/진행" 이벤트 추가가 필요합니다.

1현재 태깅 스택 (확인 결과)

실제 페이지와 GTM 컨테이너를 점검한 결과입니다. 모든 신규 작업은 주력 컨테이너 GTM-MD564Z8S에 추가하면 됩니다.

구성요소상태비고
GTM 컨테이너GTM-MD564Z8S (주력) / GTM-N78N49WX (보조)둘 다 가동 중
Mixpanel✅ GTM-MD564Z8S로 로드 (SDK cdn.mxpnl, 토큰 a8880cff…)이벤트도 GTM에서 발화
기존 데모 이벤트✅ submit_demo_request, click_to_demo_requestGTM 관리 확인됨 — 재사용
GA4✅ G-NH0RP5HMPN (주), G-CB7ZC2G0N1

핵심: Mixpanel이 이미 GTM 안에서 window.mixpanel로 살아있으므로, 폼 이탈 이벤트도 GTM에서 mixpanel.track() 한 줄로 Mixpanel과 GA4 양쪽에 보낼 수 있습니다.

2추가할 이벤트 정의 (택소노미)

이벤트명발생 시점용도필수
form_start폼 첫 필드에 최초 포커스폼 진입(작성 시작) 모수필수
form_field_blur각 필드에서 포커스 이탈어느 필드까지 도달/입력했나권장
form_abandon작성 시작 후 미제출 상태로 페이지 이탈이탈 발생 + 마지막 필드권장
submit_demo_request제출 완료 (기존)전환 — 수정 불필요—

이 정의로 만들 핵심 지표: ① 폼 진입율(click_to_demo_request→form_start), ② 폼 완료율(form_start→submit_demo_request), ③ 이탈 필드 분포(어느 필드에서 멈추는가).

3GTM 구현 단계

권장 방식은 Custom HTML 리스너 태그 1개로 모든 이벤트를 dataLayer에 밀어넣고, GTM 트리거/태그로 GA4·Mixpanel에 전달하는 구조입니다. 폼 구조가 바뀌어도 강건합니다.

3-1. 리스너 태그 (Custom HTML) 필수

GTM > 태그 > 새로 만들기 > 유형 맞춤 HTML. 트리거는 특정 페이지뷰(경로에 /solutions/demo-request 포함) 권장.

<!-- Demo Form Abandonment Listener -->
<script>
(function () {
  // 데모 신청 폼 필드 id (실제 페이지에서 확인된 값)
  var FIELD_IDS = ['form_name','form_person-information','form_email',
    'form_phone','form_company','form_mau','form_solutions','form_content'];
  function isField(el){ return el && el.id && FIELD_IDS.indexOf(el.id) >= 0; }

  var started = false, submitted = false, lastField = null;
  window.dataLayer = window.dataLayer || [];

  // 1) 폼 시작 (최초 1회)
  document.addEventListener('focusin', function(e){
    if (isField(e.target) && !started){
      started = true;
      dataLayer.push({ event:'form_start', form_name:'demo_request' });
    }
  });

  // 2) 필드별 진행 (포커스 이탈 시)
  document.addEventListener('focusout', function(e){
    if (isField(e.target)){
      lastField = e.target.id;
      dataLayer.push({ event:'form_field_blur', form_name:'demo_request',
        field_id:e.target.id, field_filled: !!(e.target.value && String(e.target.value).trim()) });
    }
  });

  // 3) 제출 클릭 표시 (이탈과 구분)
  var btn = document.getElementById('demo_request_submit_button');
  if (btn) btn.addEventListener('click', function(){ submitted = true; });

  // 4) 이탈: 작성 시작 + 미제출 + 페이지 떠남
  document.addEventListener('visibilitychange', function(){
    if (document.visibilityState === 'hidden' && started && !submitted){
      dataLayer.push({ event:'form_abandon', form_name:'demo_request',
        last_field: lastField || '(none)' });
    }
  });
})();
</script>

3-2. 데이터 영역 변수 (Variables) 권장

GTM > 변수 > 사용자 정의 변수 > 데이터 영역 변수로 아래 3개 생성:

  • DLV - field_id → 데이터 영역 변수 이름 field_id
  • DLV - field_filled → field_filled
  • DLV - last_field → last_field

3-3. 트리거 (Triggers) 필수

GTM > 트리거 > 새로 만들기 > 유형 맞춤 이벤트. 이벤트 이름에 각각:

  • form_start
  • form_field_blur
  • form_abandon

3-4. GA4 이벤트 태그 필수

이벤트별로 GA4 이벤트 태그 생성(측정 ID = 기존 G-NH0RP5HMPN 구성 변수 재사용). 예: form_start

  • 이벤트 이름: form_start
  • 이벤트 매개변수: form_name = demo_request / (blur 태그는) field_id={{DLV - field_id}}, field_filled={{DLV - field_filled}}
  • 트리거: 해당 맞춤 이벤트 트리거

3-5. Mixpanel 이벤트 태그 (Custom HTML) 필수

Mixpanel이 이미 GTM에 있으므로 window.mixpanel을 그대로 사용합니다. 이벤트별 태그 1개씩(트리거만 다르게):

<!-- Mixpanel: form_start -->
<script>
  if (window.mixpanel && mixpanel.track) {
    mixpanel.track('form_start', { form_name: 'demo_request' });
  }
</script>

form_field_blur / form_abandon 태그는 위와 동일 패턴이며 속성만 변수로:

<script>
  if (window.mixpanel && mixpanel.track) {
    mixpanel.track('form_field_blur', {
      form_name: 'demo_request',
      field_id: {{DLV - field_id}},
      field_filled: {{DLV - field_filled}}
    });
  }
</script>
태그 발화 순서: Mixpanel Custom HTML 태그가 리스너보다 먼저 뜨지 않도록, 각 Mixpanel 태그의 트리거를 해당 맞춤 이벤트로 두면 자연히 이벤트 발생 후에만 실행됩니다. (별도 순서 설정 불필요)

4검증 방법

  1. GTM 미리보기(Tag Assistant) 실행 → /solutions/demo-request 접속 → 폼 첫 칸 클릭 시 form_start, 칸 이동 시 form_field_blur, 제출 없이 탭 닫기/전환 시 form_abandon 발화 확인.
  2. GA4 실시간(DebugView)에서 같은 이벤트 수신 확인.
  3. Mixpanel Live View에서 form_start 등 도착 확인.
  4. (OCEO) 자동 브라우저 트래킹 QA 스크립트로 form_start/submit_demo_request 발화를 재현 검증 — 요청 시 OCEO에서 대행.

5분석 설정 (담당자 참고)

태깅 완료 후 Mixpanel에서 아래 퍼널을 구성하면 이탈 지점이 보입니다:

퍼널: click_to_demo_request → form_start → submit_demo_request
→ ① 클릭 후 폼 작성을 아예 시작 안 하는지(진입 이탈) ② 작성 시작 후 제출에서 막히는지(작성 이탈) 구분
이탈 필드 분석: form_abandon을 last_field 속성으로 세그먼트 → 어느 칸에서 가장 많이 포기하는지 (예: 연락처/직책 등 마찰 필드 식별)

6담당자 체크리스트

  • 리스너 태그(3-1) 생성 + 데모페이지 트리거 연결
  • 데이터 영역 변수 3개(3-2) 생성
  • 맞춤 이벤트 트리거 3개(3-3) 생성
  • GA4 이벤트 태그 생성(3-4) — 측정 ID 기존 재사용
  • Mixpanel Custom HTML 태그 생성(3-5)
  • GTM 미리보기로 4종 이벤트 발화 검증(4)
  • GA4 DebugView · Mixpanel Live 수신 확인
  • 버전 게시(Submit/Publish) + 변경 메모 기록
문의: 이벤트 정의·속성 명세나 퍼널 설계가 더 필요하면 OCEO 팀(또롱이/크롱)에서 표준 택소노미와 검증을 지원합니다.
